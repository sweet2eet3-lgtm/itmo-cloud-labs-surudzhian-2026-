# Лабораторная работа №3. Исследование Cloud Storage

## 1. Цель работы

Ознакомиться с основными принципами работы облачного хранилища Google Cloud Storage, изучить различные модели хранения данных, научиться создавать бакеты, загружать и перемещать объекты, управлять публичным доступом и получать ссылки на файлы.

## 2. Ход работы

### 2.1. Изучение моделей хранения данных

Перед выполнением практической части были рассмотрены три основные модели хранения данных:

- **Блочное хранилище (Block Storage)** — хранит данные в виде отдельных блоков. Используется преимущественно для виртуальных машин и баз данных.
- **Файловое хранилище (File Storage)** — организует данные в виде файлов и каталогов, поддерживает иерархическую структуру.
- **Объектное хранилище (Object Storage)** — хранит данные как объекты, состоящие из содержимого, метаданных и уникального идентификатора.

Google Cloud Storage относится к объектным хранилищам. Данные размещаются в бакетах и доступны через Google Cloud Console, API и специальные утилиты.

### 2.2. Создание Cloud Storage Bucket

В учебном проекте `cloud-platforms-as-the-basis` был открыт сервис Google Cloud Storage.

Через раздел **Buckets → Create** создан новый бакет со следующими параметрами:

| Параметр | Значение |
|---|---|
| Bucket name | `asurudzhian-lab3-2026` |
| Location type | Region |
| Location | europe-west1 (Belgium) |
| Storage class | Standard |
| Access control | Uniform |
| Public access prevention | Not enforced |
| Protection | Soft Delete |

Для хранения выбран класс Standard, подходящий для объектов, к которым требуется регулярный доступ.

Режим Uniform обеспечивает централизованное управление разрешениями на уровне бакета с использованием IAM.

После создания бакет появился в списке Cloud Storage.

### 2.3. Загрузка изображений

В созданный бакет через **Upload → Upload files** были загружены четыре изображения:

| Файл | Размер |
|---|---|
| IMG_7400.JPG | 90.2 KB |
| IMG_7401.JPG | 43.4 KB |
| IMG_7402.JPG | 56.1 KB |
| IMG_7403.JPG | 52.9 KB |

После завершения операции Google Cloud Console отобразила сообщение об успешной загрузке четырёх файлов.

Все изображения стали доступны в разделе Objects созданного бакета.

### 2.4. Создание папки и перемещение файлов

Для организации объектов внутри бакета была создана папка:

`lab3-images`

После этого файлы были последовательно перемещены из корневой директории в созданную папку через контекстное меню **Move**.

При перемещении в качестве назначения выбиралась папка `lab3-images`, расположенная внутри того же бакета.

Итоговая структура:

```text
asurudzhian-lab3-2026/
└── lab3-images/
    ├── IMG_7400.JPG
    ├── IMG_7401.JPG
    ├── IMG_7402.JPG
    └── IMG_7403.JPG
```

Перемещение завершилось успешно. Все четыре файла отображались внутри новой папки.

В объектном хранилище такая структура обычно реализуется с помощью префиксов имён объектов, позволяющих организовывать их в виде логических каталогов.

### 2.5. Настройка публичного доступа

Для предоставления публичного доступа к изображениям был открыт раздел **Permissions** созданного бакета.

В настройки IAM добавлен новый участник:

- **Principal:** `allUsers`
- **Role:** `Storage Object Viewer`

Роль Storage Object Viewer предоставляет разрешения на чтение объектов Cloud Storage.

Принципал `allUsers` обозначает всех пользователей интернета, включая неавторизованных.

После сохранения политики Google Cloud Console отобразила статус:

`Access granted to public principals`

Таким образом, бакет был настроен для публичного чтения объектов.

При этом права на изменение и удаление объектов публичным пользователям не предоставлялись.

### 2.6. Получение публичной ссылки

Для проверки доступа была открыта папка `lab3-images`.

Через контекстное меню изображения `IMG_7400.JPG` получена ссылка на объект:

`https://storage.googleapis.com/asurudzhian-lab3-2026/lab3-images/IMG_7400.JPG`

При переходе по ссылке браузер успешно отобразил изображение.

Это подтвердило работоспособность ссылки и доступность объекта по HTTP.

Дополнительно была изучена возможность предоставления прямых ссылок на изображения без необходимости перехода в интерфейс Google Cloud Console.

### 2.7. Удаление созданных ресурсов

После завершения исследования выполнена очистка учебного проекта.

Через раздел **Cloud Storage → Buckets** был удалён бакет:

`asurudzhian-lab3-2026`

В Google Cloud Console появилось уведомление:

`Deleted 1 bucket`

После удаления в списке остался только ранее существовавший учебный бакет `lab1-bucket-itmo`.

Созданные в рамках лабораторной работы ресурсы были удалены. Публичные ссылки на изображения перестали быть действующими.

## 3. Вывод

В ходе лабораторной работы были изучены основные принципы объектного хранения данных в Google Cloud Storage.

Был создан бакет с классом хранения Standard, загружены четыре изображения и организована структура хранения с помощью отдельной папки.

Практически изучены операции загрузки и перемещения объектов, настройка разрешений IAM и предоставление публичного доступа через роль Storage Object Viewer.

Получена прямая ссылка на изображение и проверено его отображение в браузере.

Исследование показало, что Google Cloud Storage позволяет удобно управлять объектами, организовывать их хранение и предоставлять доступ к данным через интернет.

После завершения работы созданный бакет был удалён.

**Цель лабораторной работы достигнута.**
